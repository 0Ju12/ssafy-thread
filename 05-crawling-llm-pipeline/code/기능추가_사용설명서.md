# ThRead 05-pjt — 추가 기능 구현 안내

기준: SSAFY 16기 Python 관통 5회차 명세서 (F601~F607 필수, F610·F611 심화).
기존 Django/Selenium/GMS 파이프라인과 11개 디자인 테마는 유지합니다.

## 1. 구현한 기능

| 기능 | 동작 | 관련 파일 |
|---|---|---|
| 원본–정제–증강 비교 | 정제 데이터의 원본 인덱스를 저장하고 AI 증강 문장과 연결, 변경 구간 강조, 검색 | `preprocess.py`, `pipeline.py`, `quality.py`, `_pair_compare.html` |
| 증강 품질 검사 | 숫자·가격 부호·퍼센트·상승/하락 반전·원문 종목명 누락 탐지, 오류 시 LLM 재시도, 검토 표시 | `quality.py`, `augment.py`, `pipeline.py`, `quality_checks` 필드 |
| 데이터 시각화 | 실제 수집 댓글 수·길이 분포·간단 단어 빈도; CSS 막대 차트 (외부 JS 차트 라이브러리 불필요) | `insights.py`, `_insights.html` |
| CSV/JSON 내려받기 | 단계별 필터, CSV UTF-8 BOM/Excel 수식 실행 위험 방어, JSON에 원본 출처·품질 결과 포함 | `views.py:export_result`, `_export_actions.html` |
| 동일 종목의 이력 비교 | 이전 저장 결과 선택, 데이터 수·단어 빈도·새로 발견/사라진 표본 댓글 비교 | `views.py:compare_history`, `insights.py`, `history_compare.html` |
| 댓글 중복 판별 보완 | 사이트가 게시물 ID를 제공하면 게시물 ID 기준으로 중복 판별; 같은 화면의 동일 문장도 구분 | `crawler.py` |
| 스트리밍 내구성 개선 | 응답 제너레이터가 아닌 파이프라인 작업 스레드에서 DB 저장; 브라우저 연결이 끊겨도 프로세스가 살아 있으면 작업 계속 | `views.py:run_stream` |

## 2. 실행

```bash
cd 05-pjt
python -m venv .venv
# Windows Git Bash
source .venv/Scripts/activate
python -m pip install -r requirements.txt
cp .env.example .env
# .env 파일에 본인 GMS_KEY 기입
python manage.py migrate
python manage.py test comments
python manage.py runserver
```

- `MODEL=gpt-6.1-sol` 로 GMS Responses API 사용. 단, 본인 GMS 권한에서 이용할 수 있는지는 실제 호출로 확인해야 합니다.
- `USE_SAMPLE_DATA=1`은 크롤링 대체만 수행합니다. `GMS_KEY`가 없다면 LLM 부적절 판정/증강/요약은 실행되지 않고 경고가 표시됩니다. 테스트는 mock으로 외부 연결 없이 작동합니다.
- 이전 버전 DB를 사용하면 **`python manage.py migrate`** 필수 (`0002_crawlresult_quality_checks`).

## 3. 새로운 사용 화면과 URL

- 홈 `/`: 11개 테마 선택, 최근 분석 이력, **이력 비교 링크**
- 결과 `/results/<pk>/`: 원본/전처리/증강 + **통계**, **차이 강조**, **품질 경고**, **파일 내려받기**
- CSV `/results/<pk>/export/csv/?stage=all` (stage: all / original / removed / clean / augmented)
- JSON `/results/<pk>/export/json/?stage=clean`
- 비교 `/results/<pk>/compare/` (비교 대상 선택 `?other=<다른 pk>`)

11개 테마 중 E(데스크), J(글래스), K(콘솔)는 **통계 인사이트**·**AI 문장 검증** 탭으로 접근합니다. 나머지 테마는 결과 페이지의 추가 섹션으로 표시됩니다.

## 4. 주의할 한계

1. **규칙 기반 품질 검사는 의미를 100% 검증하지 않습니다.** 일부 반전과 숫자 오류를 감지할 뿐, 투자 판단이나 정확성 보증이 아닙니다.
2. **키워드는 형태소 분석 결과가 아닙니다.** 띄어쓰기와 정규식을 이용한 빈도이며, 긍정·부정 감성을 산출하지 않습니다.
3. **이력 비교는 각 시점에 모은 최대 20개 표본입니다.** 댓글이 이번 표본에 없다고 실제 삭제된 것은 아닙니다.
4. **댓글 게시물 ID가 토스증권 DOM에 없을 수 있습니다.** 이 경우 화면 내 출현 순서를 활용하는 보조 판별 방식은 다른 위치의 동일 문장들을 완벽히 구분하지 못합니다.
5. **스트리밍 작업은 외부 작업 큐가 아닙니다.** 브라우저가 닫혀도 같은 서버 프로세스가 살아 있을 때만 계속 실행됩니다. 서버 종료/재시작 시 작업 보장은 Celery + Redis 등 별도 작업 큐가 필요합니다.
6. **이전에 저장한 결과**는 원본 댓글 연관 ID가 없어 문장 비교 화면에서 원본 연결 안내가 표시될 수 있습니다. 새 분석부터 출처가 연결됩니다.
7. **실제 GMS와 토스증권은 테스트되지 않았습니다.** 이 환경은 Django/Selenium/OpenAI 패키지를 설치할 수 없어 전체 통합 테스트를 실행하지 못했습니다. 프로젝트의 정적 Python 문법과 외부 의존성이 없는 보조 함수만 직접 확인했습니다.
8. SSAFY 제출용으로 모든 기능의 실제 화면 캡처를 최신 버전에서 다시 생성하세요. 기존 `screenshots` 파일은 이전 버전의 참고 이미지입니다.

## 5. 테스트

`python manage.py test comments`에 숫자·방향·종목명 검사, HTML 이스케이프, 동일 문장 수집, 출처 인덱스, 키워드 계산, 단계별 CSV/JSON, 다른 종목 비교 차단, 11개 테마 출력에 대한 새 테스트가 추가됐습니다.

실제 테스트는 사용자의 Windows 환경에서 패키지 설치 후 실행해야 합니다. `USE_SAMPLE_DATA=0` 실연동과 `GMS_KEY` 검증도 별도로 수행하십시오.
